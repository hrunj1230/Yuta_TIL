


핵심 시사점

  1. 데이터 9,000~10,000개면 페르소나 학습에 충분하다는 게 연구 컨센서스입니다. https://arxiv.org/abs/2305.11206에서는 고품질 1,000개만으로도 유의미한 결과를
  냈습니다.
  2. epoch은 1~4회가 일반적입니다. 데이터가 만 개 수준이면 3 epoch이 적정선이고, 그 이상은 과적합 위험이 커집니다.
  3. 데이터 품질 >> 데이터 양. 스캐터랩도 인터뷰에서 "양질의 데이터셋 확보에 가장 많은 노력을 기울였다"고 했습니다.

  지금 프로젝트에 적용하면

  현재 synthetic_dialogues.json의 대화 수가 수백 개 수준이라면, 3 epoch은 괜찮습니다. 데이터가 1,000개 이상으로 늘어나면 epoch을 줄이고, 검증 데이터 분리로
  과적합을 모니터링하는 게 맞습니다.

학습 시간 추정 (Colab 무료 T4)

  데이터 양에 따라 달라집니다:
  ┌───────────┬───────────────────┬──────────────┐
  │ 데이터 수 │ 총 스텝 (3 epoch) │ T4 예상 시간 │
  ├───────────┼───────────────────┼──────────────┤
  │ 100개     │ ~38               │ ~10분        │
  ├───────────┼───────────────────┼──────────────┤
  │ 500개     │ ~188              │ ~50분        │
  ├───────────┼───────────────────┼──────────────┤
  │ 1,000개   │ ~375              │ ~1.5시간     │
  ├───────────┼───────────────────┼──────────────┤
  │ 5,000개   │ ~1,875            │ ~7-8시간     │
  └───────────┴───────────────────┴──────────────┘
  계산 근거: 유효 배치 8 (batch 2 x grad_accum 4), 14B 4bit 모델 기준 T4에서 스텝당 ~1.5초.

  Colab 무료 티어 제약은 GPU 세션 최대 ~12시간 (보장은 아님), 하루 사용량 제한이 있습니다. 데이터 1,000개 이하면 한 세션에 충분히 끝나고, 그 이상이면 epoch을
  1로 줄이거나 Colab Pro를 고려해야 합니다.
