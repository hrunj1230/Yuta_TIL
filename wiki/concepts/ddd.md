# DDD

## 정의
DDD는 복잡한 소프트웨어의 핵심 도메인을 중심으로 모델을 만들고, 도메인 개념과 경계를 코드 구조와 설계에 반영하는 개발 방법이다. 소스에서는 에이전트 기반 개발 환경에서도 도메인 모델링과 설계 원칙이 여전히 중요한 역량으로 남는다는 맥락에서 언급된다.

## 주요 특징
- 도메인 개념, 업무 규칙, 경계를 명확히 모델링한다.
- 코드 구조가 실제 비즈니스 의미와 스펙을 반영하도록 설계한다.
- 에이전트가 전체 코드 흐름을 분석할 때 도메인 맥락을 이해하는 기준이 된다.
- LLM 도구가 생성한 코드나 분석 결과의 품질을 판단하는 설계 기준으로 활용될 수 있다.
- [[concepts/헥사고날-아키텍쳐|헥사고날 아키텍쳐]], [[concepts/레이어드|레이어드]], [[concepts/디자인패턴|디자인패턴]]과 함께 여전히 중요한 설계 원칙으로 언급된다.

## 응용
- 복잡한 서비스의 도메인 모델과 경계를 정의할 때 사용한다.
- 에이전트가 코드베이스를 분석하거나 변경할 때 핵심 도메인 개념을 파악하는 기준으로 활용한다.
- LLM 기반 개발 도구가 생성한 코드가 실제 스펙과 업무 규칙을 적절히 반영했는지 평가하는 데 사용한다.
- [[entities/아틀라스|아틀라스]]처럼 코드 지도나 구조 분석을 다루는 시스템에서 코드 흐름과 도메인 의미를 연결하는 데 활용될 수 있다.
