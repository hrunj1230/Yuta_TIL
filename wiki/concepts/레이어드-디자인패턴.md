# 레이어드 디자인패턴

## 정의
레이어드 디자인패턴은 애플리케이션을 프레젠테이션, 도메인, 인프라 등 여러 계층으로 나누고 각 계층의 책임과 의존 관계를 분리하는 소프트웨어 설계 방식이다. 소스의 맥락에서는 [[concepts/헥사고날-아키텍쳐|헥사고날-아키텍쳐]], [[concepts/ddd|ddd]]와 함께, [[concepts/에이전트|에이전트]]와 대규모 언어 모델 기반 개발이 확산되어도 여전히 중요한 전통적 설계 원칙으로 언급된다.

## 주요 특징
- 애플리케이션을 기능적 책임에 따라 여러 계층으로 분리한다.
- 각 계층은 자신의 역할에 집중하며, 다른 계층과의 결합도를 낮추는 것을 목표로 한다.
- 일반적으로 프레젠테이션 계층, 애플리케이션 계층, 도메인 계층, 인프라 계층 등으로 구성된다.
- 코드의 변경 범위를 계층 단위로 제한하여 유지보수성과 테스트 용이성을 높인다.
- 자동화된 코드 분석이나 수정이 이루어질 때도 명확한 구조와 경계를 제공해 작업 품질을 높일 수 있다.

## 응용
- 웹 애플리케이션에서 사용자 인터페이스, 비즈니스 규칙, 데이터 접근 로직을 분리할 때 사용된다.
- 복잡한 도메인 로직을 인프라 구현과 분리하여 테스트 가능성을 높이는 데 활용된다.
- 대규모 코드베이스에서 팀별 책임 영역을 명확히 나누는 설계 기준으로 사용된다.
- [[concepts/에이전트|에이전트]]가 기존 코드를 분석하거나 수정하는 환경에서 코드 구조를 이해하기 쉽게 만드는 기반으로 활용될 수 있다.
- [[concepts/바이브코딩|바이브코딩]]처럼 인공지능 기반 개발 흐름에서도 일관된 아키텍처 경계를 유지하는 데 도움이 된다.
